# src→next-app 功能全量迁移 - 实现方案（Batch 0）

> 生成时间：2025-12-26  
> 约束：`src/` 保留但不作为入口；迁移后保持 `src/` 原有功能颗粒度；UI 采用 `UI设计.md` 选定 v4 √；新增/修改文案必须 i18n。

## 0. 目标与范围

### 0.1 目标（主人价值）
- 统一入口：以 `next-app/` 为唯一入口，避免“旧静态 UI + Next UI”双入口割裂。
- 功能齐全：把 `src/` 下剩余功能（Settings / API Keys / Providers / Auth Files / Config / System / OAuth）迁移到 `next-app/`。
- 体验升级：统一页面骨架、状态覆盖（loading/empty/error/disabled/confirm/dirty），交互可恢复、可回滚。
- 架构可拓展：明确 page / component / server api / management client 的职责边界，避免页面无限膨胀（单文件>600行必须拆分）。

### 0.2 非目标（明确不做）
- 不删除旧版 `src/`（仅保留对照/回滚）。
- 不引入账号体系/RBAC（延续现状：无登录用户概念）。
- 不把敏感管理密钥写入数据库/前端存储（localStorage/sessionStorage/URL 均禁止）。

## 1. 总体架构（推荐分层）

```
UI (Client Components)
  └─ next-app/app/**/page.tsx  +  next-app/components/**
        └─ 仅通过 fetch 调用 Next /api/*

Next API Routes (Server)
  └─ next-app/app/api/**/route.ts
        └─ 调用 lib/management/*（server-only）

Management Access (Server-only)
  └─ next-app/lib/management/**
        └─ 统一封装 management API：鉴权、错误归一、限流/分页参数、脱敏

DB（可选，仅用于现有 usage/pipeline/pricing 等）
  └─ next-app/lib/db.ts + prisma/schema.prisma
```

关键原则：
- **浏览器永远只请求 Next 的 `/api/*`**（不得直连 management API）。
- **`CLIPROXY_MANAGEMENT_KEY` 只在服务端读取**，且只用于 route handler 与 server-only client。
- **错误返回统一 envelope**，保证 UI 的 Empty/Error/Toast 可复用、可 i18n。

## 2. 模块颗粒度与路由映射（保持与 src 一致）

> 迁移后的模块颗粒度必须与旧 `src/` 侧边栏一致（主人要求）。建议按 6 块落地：

| 旧模块（src/hash 语义） | Next 路由（next-app） | 备注 |
|---|---|---|
| 登录/连接检查（无账号） | `/login` | 作为 Connect & Health 中枢，三态（env 缺失/失败/成功） |
| 基础设置（debug/proxy/retry 等） | `/settings` | Tabs 或分区表单（保存/回滚） |
| API Keys | `/settings/api-keys`（推荐独立路由） | 保持颗粒度清晰，避免塞进一个超大 settings 页 |
| Providers（不含 OAuth 授权流程） | `/settings/providers` | Provider keys（OAuth 统一到 `/oauth` 登录中心） |
| Auth Files | `/auth-files` | 表格 + 搜索/分页 + Drawer 详情 + 删除 confirm |
| Config Editor | `/config` | SaveBar + DirtyGuard，保存失败不丢内容 |
| System / Diagnostics | `/system` | 版本/诊断复制/健康信息 |

不在本迁移内改动但必须回归验证：
- `/usage` `/logs` `/pipeline` `/pricing`（已有 Next 页面与 API）

## 3. 数据结构与接口约定（TS 契约）

### 3.1 统一 API 返回体（推荐强制）

```ts
export type ManagementErrorCode =
  | 'ENV_MISSING'
  | 'UNAUTHORIZED'
  | 'UPSTREAM_ERROR'
  | 'VALIDATION_ERROR'
  | 'NOT_FOUND'
  | 'RATE_LIMITED'
  | 'UNKNOWN';

export interface ManagementError {
  code: ManagementErrorCode;
  message: string; // 需 i18n（前端使用 key 映射或后端返回 code）
  retryable?: boolean;
  httpStatus?: number;
  details?: unknown; // 严禁包含密钥
}

export type ApiResult<T> =
  | { data: T; error?: never }
  | { data?: never; error: ManagementError };
```

### 3.2 核心业务类型（最小集合，可逐步扩展）

```ts
export interface ConnectionStatus {
  connected: boolean;
  reason?: string;
  serverVersion?: string;
}

export interface SettingsSnapshot {
  // key 建议使用枚举/联合类型，不直接用 string
  values: Record<string, unknown>;
  lastUpdated?: string;
}

export interface ApiKeyEntry {
  id: string;
  maskedKey: string;
  createdAt?: string;
  customHeaders?: Record<string, string>;
}

export interface ProviderCredential {
  providerId: string;
  apiKeyMasked?: string;
  oauthUrl?: string;
  status?: 'ok' | 'missing' | 'error';
}

export interface AuthFileEntry {
  name: string;
  type?: string;
  size?: number;
  modtime?: string;
  stats?: Record<string, unknown>;
}

export interface ConfigDocument {
  content: string;
  format?: 'json' | 'yaml' | 'text';
  dirty?: boolean;
  lastSaved?: string;
}
```

## 5. 关键实现策略（防翻车项）

### 5.1 server-only 门禁（必做）
- 在 `next-app/lib/management/*` 顶部引入 `server-only`（或等价机制），禁止 client 侧 import。
- UI 侧禁止出现 `CLIPROXY_MANAGEMENT_KEY`，禁止把上游错误原样透传到浏览器（尤其是 headers/Authorization）。

### 5.2 错误归一与可恢复交互（必做）
- `/api/*` 统一返回 `ApiResult<T>`。
- UI 层只依赖 `error.code/retryable` 决定：Retry、Copy diagnostics、降级只读等。

### 5.3 分页/limit（默认打开）
- Auth Files / Logs / Keys 等列表默认 limit（建议 ≤ 100/次），避免一次性渲染过多 DOM。
- 允许后续加虚拟列表，但 Batch 0 先保证“不卡 + 可用”。

### 5.4 Config Editor 安全（重点）
- 保存失败：**不丢编辑内容**（DirtyGuard + SaveBar）。
- 保存前：确认提示（不可逆/覆盖风险）；提供“下载备份”入口。

### 5.5 i18n 约束（主人已确认必须）
- 统一使用 Next 的 i18n context（例如 `useI18n().t()`）。
- key 命名建议：
  - `nav.*`（侧边栏）
  - `<route>.title` / `<route>.desc`
  - `<route>.action.*`
  - `common.*`（Confirm/Retry/Copy/Save/Cancel）
