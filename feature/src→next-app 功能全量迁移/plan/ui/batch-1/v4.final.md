# v4（综合推荐稿）— OAuth 登录中心 / Batch 1

## 1) 最终推荐（收敛结论）
- 采用“**独立 OAuth 登录中心页面**”作为主体验（建议 `/oauth`），而不是把所有能力塞回 `/settings/providers` 的 OAuth Tab。
- 页面结构固定为“**ProviderGrid + AuthFlowPanel**”两列布局（移动端自动堆叠），并明确状态机与边界（超时/错误重置/切换确认/卸载清理）。
- iFlow Cookie 登录作为 **高级折叠区**：可用但不干扰主流程。

## 2) 关键交互规范（强制）
### 2.1 状态机与节奏
- `idle → generating → polling → success`
- `polling → error → (3s) → idle`
- `polling → timeout → idle`（5 分钟上限）
- `polling` 时展示：Badge（等待）+ 倒计时 + Progress（增强可感知）

### 2.2 切换/重置保护
- 当存在 `oauthUrl` 或正在 `polling` 时：
  - 切换 Provider / 点击 Reset → 弹 confirm（明确“将取消当前流程”）
  - 用户取消则保持现状

### 2.3 成功闭环（必须有下一步）
- 成功后展示结果卡片（或轻量 overlay）：
  - 主按钮：`查看 Auth Files`（跳转 `/auth-files`）
  - 次按钮：`复制状态信息`（便于排障/留痕）

### 2.4 安全提示（必须可见）
- 授权 URL 含 `state`：提示“请勿分享”；复制时 toast 再次提醒。
- Cookie 登录区域提示“仅限本人使用/提交后清空”；不做持久化。
- 浏览器只请求 Next `/api/*`（管理密钥只在服务端）。

## 3) 组件拆分（实现阶段按此拆，避免单文件 >600 行）
- `OAuthCenterPage`（page）
- `ProviderGrid` / `ProviderCard`
- `AuthFlowPanel`
  - `AuthUrlDisplay`（Copy/Open + 单行截断）
  - `PollingProgress`（Badge + progress + timeLeft）
  - `ResultCard`（success/error/timeout）
- `IflowCookieLogin`（Accordion）
- `useOAuthFlow`（hook：状态机 + 轮询 + timeout + cleanup）

## 4) 争议点（需主人拍板）
详见：`disputes.md`（<=8 条）

## 5) 验收点（<= 12）
1) 生成 URL → Copy/Open → 轮询 WAIT → OK/ERROR/TIMEOUT 全链路可走通
2) 轮询间隔 2s，超时 5min，退出页面会 stop polling
3) ERROR 后 3s 自动 reset，且期间能复制错误详情
4) 切换 Provider/重置会 confirm，避免误丢状态
5) iFlow Cookie 登录入口仅 iFlow 可见且可折叠
6) Cookie 提交有必填校验 + loading + 结果字段展示
7) 成功后 CTA 可跳转 `/auth-files`，且提示“可查看凭证文件”
8) URL/cookie 不被持久化（刷新/离开即清空）
9) 文案全部可 i18n（en/zh 都覆盖）
10) 暗色主题对比度足够，状态色不会刺眼或难辨认
11) 移动端不横向滚动，按钮与输入可用
12) 任何敏感操作（重置/取消）有明确反馈（toast/提示文案）
