# v2（专家A：Gemini UI）要点摘要 — OAuth 登录中心 / Batch 1

## 1) 信息层级建议（偏视觉与可感知）
- 顶部 PageHeader：标题 + 一句说明（“生成授权链接 / 轮询状态 / 可选 Cookie 登录”）+ 右侧「刷新状态」轻操作。
- Provider 区做成“栅格卡片”：icon + 名称 + 能力标签（URL / Cookie），选中态明显（border-primary + ring/背景微亮）。
- 授权流程区以“单卡片 Step 面板”呈现：把 WAIT/OK/ERROR 的状态放到最显眼位置（Badge + 倒计时 + 进度条）。

## 2) 关键视觉亮点（专家建议保留）
1) **沉浸式状态感知**：Badge + 倒计时 + Progress，把“轮询中”变成可感知的过程，减少用户焦虑。
2) **成功态强引导**：成功后不仅 toast，建议在流程卡片内用 success overlay/结果卡片给“下一步”CTA（去 Auth Files）。
3) **高级能力折叠**：iFlow Cookie 登录用折叠区收纳，避免干扰主路径但入口可发现。

## 3) 交互细节建议（可落地）
- 复制按钮建议配 Tooltip/Toast（“已复制，请勿分享”）；URL 显示单行截断，hover 显示完整。
- 错误区要提供“可复制错误详情”与“重试/重置”，并在 3 秒后自动 reset。

## 4) 验收点（<= 10）
1) Provider 栅格在移动端自动变为 2 列，卡片点击区域足够大
2) 授权链接区域不换行撑破布局，复制/打开按钮在窄屏可换行但不挤压输入框
3) WAIT 状态必有倒计时与进度条反馈
4) OK 状态出现“去 Auth Files”按钮
5) ERROR 状态出现可复制的错误摘要 + 重试/重置
6) iFlow 才显示 Cookie 折叠区
7) Cookie 提交时禁用输入并显示 loading
8) 超时后停止轮询并显示“已超时，可重新生成”
9) 全部文案可 i18n（实现阶段补 key）
10) 暗色主题下对比度足够（状态色/边框/文字）
