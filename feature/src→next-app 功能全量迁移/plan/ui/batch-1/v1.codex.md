# v1（Codex）草图稿 — OAuth 登录界面迁移与重设计 / Batch 1

## 1) 页面定位与信息架构
- 目标：把“OAuth 授权/回填/轮询/成功引导”从 `/settings/providers` 的简版 Tab 中抽出来，形成一页完成的“登录中心”体验。
- 建议路由（实现阶段二选一即可）：
  - `/oauth`：清晰独立，适合从侧边栏直接进入
  - `/settings/providers?tab=oauth`：作为“快捷入口”，但本次主体验仍建议独立路由

## 2) 核心组件拆分（便于复用与后续扩展）
- `OAuthCenterPage`：PageHeader + 两列布局（ProviderGrid + AuthFlowPanel）
- `ProviderGrid`：ProviderCard 列表（icon/名称/能力标签/说明/选中态）
- `AuthFlowPanel`：
  - `CreateUrlSection`：生成链接按钮 + “生成中”状态
  - `UrlDisplaySection`：单行截断 URL + Copy/Open + “复制成功”反馈
  - `PollingStatusSection`：Badge + progress/倒计时 + Stop/Reset
  - `ResultSection`：成功/失败的结果卡片（错误详情可复制）
- `IflowCookieLogin`：Accordion 内的 Cookie 输入 + 提交 + 结果展示（email/expired/path/type）

## 3) 交互流程（按旧版行为对齐，补齐体验）
### 3.1 URL OAuth（codex/anthropic/antigravity/gemini-cli/qwen/iflow）
1) 选择 Provider（默认 codex）
2) 点击“生成授权链接”
3) UI 显示：
   - URL 输入展示（只读/可复制/可打开）
   - 状态 Badge：WAIT（黄色）→ OK（绿色）/ ERROR（红色）
   - 进度：建议显示“剩余时间”（上限 5 分钟）+ progress bar
4) 轮询策略建议：
   - 2 秒轮询一次（对齐旧版）；超时 5 分钟自动停止并提示“已超时，可重试”
5) 成功：
   - toast：成功
   - 引导卡片：主按钮“去 Auth Files 查看”（跳转 `/auth-files`）
   - 可选：提示“已自动刷新/可点击刷新”（实现阶段决定是否自动触发刷新）
6) 失败：
   - 展示错误摘要（可复制）
   - toast：失败
   - 3 秒后自动 reset（对齐旧版）；同时提供“立即重试/重置”按钮

### 3.2 iFlow Cookie 登录（高级）
- 默认折叠（Accordion），仅当 provider=iFlow 时出现入口（避免干扰主流程）。
- 校验：
  - 空值：提示必填
  - 提交中：按钮 loading + 禁用输入
- 结果：
  - 成功：展示 email/expired/path/type；toast 成功；CTA“去 Auth Files 查看”
  - 失败：展示 error 摘要 + 可复制

## 4) 状态覆盖（必须有对应 UI）
- loading：生成链接中 / 轮询中
- empty：未生成链接（提示“请选择 provider 并生成”）
- error：网络/后端错误（可重试）
- timeout：超过 5 分钟（可重试）
- disabled：正在提交/轮询时禁用切换（或切换需 confirm）
- confirm：切换 provider 或 reset 时，如会丢当前 URL/state，弹确认

## 5) 设计验收点（<= 10 条）
1) Provider 卡片选中态清晰，且能区分 URL OAuth / Cookie OAuth 能力
2) URL 显示支持一键 Copy / Open，且长 URL 不撑破布局
3) WAIT/OK/ERROR 状态颜色与文案明确，且带进度/倒计时
4) 超时后停止轮询并给出可操作 CTA（Retry/Reset）
5) 失败可复制错误详情，且 3 秒后自动 reset 让用户重新开始
6) 成功后有明确“下一步”引导（去 Auth Files）
7) iFlow Cookie 登录独立且可折叠，不干扰主流程
8) 全程不暴露管理密钥，浏览器只请求 Next `/api/*`
9) 全部用户可见文案可 i18n（实现阶段补齐 key）
10) 页面在暗色主题下对比度足够（文字/边框/状态色）
