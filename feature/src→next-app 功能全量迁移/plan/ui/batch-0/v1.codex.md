# v1（Codex）草图稿 — src→next-app 功能全量迁移 / Batch 0

## 1) 总体设计方向（延续 next-app 现有审美）
- 主题：延续现有 `theme-night` 的暗色玻璃拟态（`bg-card/60 + border-border/60 + backdrop-blur`），并确保 `theme-day` 下同样可读。
- 页面结构：统一采用“上方 PageHeader（Title+Subtitle+Actions）+ 下方 Card 容器承载主要交互”。
- 信息密度：默认“中密度”，关键操作（保存/删除/清空/下载）集中在页头右侧；次级操作收纳到 dropdown 或 card header。
- 状态一致性（必须）：loading/empty/error/disabled/confirm/toast 组件化复用，避免每页各写一套。
- i18n：所有文案（标题/按钮/提示/confirm）必须使用 `useI18n().t(key)`，不新增硬编码。

## 2) 路由与信息架构建议
- `/` Dashboard：更像“控制台首页”，展示连接状态与快捷入口，而不是纯文字欢迎页。
  - 上方 3–4 个状态卡：Connection / Server Version / Data Pipeline / Last Updated
  - 下方快捷入口卡：Settings / Providers / Auth Files / Logs
- `/login`：从“登录”语义转为“连接/健康检查/环境提示”。
  - 当 env 缺失：展示缺失项清单 + 一键复制示例 `.env` 片段（复制按钮）+ 文档链接
  - 当连接失败：展示错误摘要 + Retry + Diagnostics（折叠详情）
- `/settings`：基础设置页（开关/输入项）为主，不要把所有内容塞成一页巨表。
  - 建议结构：左侧（或顶部）分组 Tabs：Network / Logging / Quota / Advanced
  - 每个分组一个 Card，内含表单项 + 保存按钮（或按项立即生效但提供回滚）
- `/settings/providers`：Providers & OAuth
  - 上半区：Provider Key 管理（Gemini/Codex/Claude…）+ 连通性提示（例如“未配置/已配置” badge）
  - 下半区：OAuth 操作卡（获取 URL → 打开新窗口 → 回填提示/复制）
- `/auth-files`：Auth Files 列表
  - 顶部 FilterBar：Type filter + Search + Page size（可选）+ Refresh
  - 主列表：卡片式列表或表格（建议表格：更利于密集信息 + 操作列）
  - 行内操作：Details（抽屉）/ Download / Delete（confirm）
- `/config`：Config Editor
  - 顶部：状态条（dirty/last loaded/last saved）+ Save/Reload/Download
  - 主体：编辑器区域（Monospace、行号可选）+ 右侧帮助/校验结果（可选）
- `/system`：系统信息与诊断
  - Card 1：版本与构建信息（UI / Server / Build date）
  - Card 2：连接信息（Base URL、环境变量状态）
  - Card 3：诊断与复制（Copy diagnostics JSON、查看最近错误）

## 3) 交互细节（重点，避免“只是好看但不好用”）
- 危险操作统一 confirm：删除 auth files、清空 logs、覆盖写入 config 都必须二次确认，文案明确“不可逆”。
- 表单保存节奏：
  - 保存中：按钮 disabled + spinner
  - 成功：toast（success）+ subtle 状态 chip（例如 “Saved”）
  - 失败：toast（error）+ 回滚 UI 值（若是 toggle/输入项）
- 列表体验：
  - 搜索输入：300ms debounce（避免每字符请求）；空态给出“清空筛选/重置”按钮
  - 大列表：分页优先；如果后端仅支持全量，则前端分页+虚拟滚动（后续实现方案再定）
- 诊断信息可复制：错误摘要、连接信息、OAuth URL 都提供 Copy 按钮（带 “copied” feedback）。

## 4) 组件拆分建议（可复用优先）
- `components/layout/*`：保持 Sidebar；建议补一个通用 `PageHeader`（可参考 `UsagePageHeader` 风格）。
- `components/ui/*`：优先复用 shadcn；危险操作尽量用 Dialog/AlertDialog（替代 `window.confirm`）。
- 新增领域组件（建议）：
  - `components/common/StatusCards`：用于 Dashboard、Login、System
  - `components/common/EmptyState` / `ErrorState`：统一空态与错误态
  - `components/common/CopyButton`：统一复制交互（带 toast）
  - `components/settings/*`、`components/providers/*`、`components/auth-files/*`、`components/config/*`

## 5) 验收点（<=10）
1. 所有侧边栏导航项均可打开且无断链（含新建页面）。
2. 新页面统一 PageHeader + Card 结构，视觉与现有 logs/usage 风格一致。
3. loading/empty/error/disabled/confirm/toast 状态在关键页面可见且体验一致。
4. 危险操作均有二次确认，且提示不可逆。
5. i18n 覆盖新页面文案；中英切换可用且无硬编码。
6. Dashboard 能一眼看懂“当前系统是否可用/下一步做什么”。
7. Auth Files 支持筛选+搜索+分页（或等价体验），并有详情抽屉。
8. Config Editor 有脏态提示，保存失败不丢编辑内容。
9. System 页可复制诊断信息，便于排障。
10. day/night 两种主题下均可读（重点检查表单与卡片对比度）。
