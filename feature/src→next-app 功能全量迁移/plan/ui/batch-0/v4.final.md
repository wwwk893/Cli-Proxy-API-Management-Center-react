# v4（综合推荐稿）— src→next-app 功能全量迁移 / Batch 0

## 0) 最终选择与一句话结论
- 推荐采用：**“统一 PageHeader + 主 Card 容器 + 复用状态组件”的管理台范式**，并把 `/login` 定位为“连接/健康检查/环境提示”（无账号体系）。
- 视觉：延续 next-app 暗色玻璃拟态 + shadcn/ui；交互：统一 confirm/toast/dirty guard；信息架构：以 `/settings` 为配置中枢，其余按领域拆页。

## 1) 关键信息架构（最终决策）
- `/` Dashboard（增强）
  - 顶部 Status Cards：Connection / Server Version / Data Pipeline / Last Updated
  - 下方 Quick Actions：跳转 Settings / Providers / Auth Files / Config / Logs
  - 下方 Recent Activity（可选）：最近 20 行 logs 摘要（只展示，不在此页清空）
- `/login`（最终定位：Connect & Health）
  - 默认不让用户输入管理密钥：只展示 env 是否配置、连接是否成功、错误摘要与重试。
  - （可选，开发态）提供“临时覆盖连接信息”的入口，但必须显式标注风险与仅开发可用（是否落地由实现方案再定）。
- `/settings`
  - 分组/Tab：Network（Proxy/Retry）/ Logging（request-log/logging-to-file/ws-auth）/ Quota / Advanced（debug 等）
  - 每个分组一个 Card：字段 + 说明 + Save（或按项立即生效但保留失败回滚）。
- `/settings/providers`
  - Provider Cards（Gemini/Codex/Claude…）：状态 badge（已配置/未配置）+ 编辑/删除
  - OAuth 区：按 provider 分类的操作卡（获取 URL → 打开 → 回填/确认）
- `/auth-files`
  - 顶部 FilterBar：Type / Search / Page size（可选）/ Refresh
  - 主体优先用“表格”承载密集信息：type/name/modtime/size/stats + actions
  - Details 用 Drawer（抽屉）展示统计与元信息；Delete/Batch delete 必须 confirm
- `/config`
  - 顶部 SaveBar：dirty 状态、last loaded、Save/Reload/Download
  - 主体编辑区：Monospace + 可选行号；右侧（可选）显示校验/提示（例如 YAML 解析错误）
  - 离开页面若 dirty：拦截并提示（DirtyGuard）
- `/system`
  - 版本与构建信息 + 连接信息 + 环境变量检测（缺失项高亮）
  - Copy diagnostics（JSON/文本）按钮，便于排障

## 2) 统一交互规范（最终决策）
- Confirm：所有不可逆操作使用 shadcn `AlertDialog`，文案必须包含“不可逆”，并把危险按钮设为 destructive。
- Toast：所有异步操作（保存/删除/刷新/下载触发）必须有 toast（success/error），避免“点了没反应”。
- Loading：Card 内使用 Skeleton（或轻量 spinner），并禁用重复提交。
- Error：ErrorState 统一组件：错误摘要 + Copy + Retry（避免用户无从排障）。
- Empty：EmptyState 统一组件：icon + 一句说明 + 主按钮引导（如“去配置 Providers”）。
- i18n：新增页面/组件所有文案必须来自 `useI18n().t(key)`；新增 key 统一补齐 en/zh（按现有 `i18n-context.tsx` 字典）。

## 3) 争议点收敛（v2 vs v3 vs v1）
- “/login 是否输入 base/key？”
  - v2 倾向保留输入并存 localStorage；v1/v3 倾向以“健康检查”替代账号登录。
  - **最终：默认采用 server env（不在客户端输入密钥）**；如确需保留“临时覆盖”，仅作为开发态可选项并在实现方案中单独评审安全影响。
- “Auth Files 列表用卡片还是表格？”
  - v2 建议 Grid/List 切换；v1/v3 更偏向表格（密度更高）。
  - **最终：表格为主 + Drawer 详情**（更符合运维/管理台场景）。
- “confirm 使用 window.confirm 还是 Dialog？”
  - v3 明确要求统一 ConfirmDialog。
  - **最终：统一 AlertDialog**（后续实现落地）。

## 4) 验收点（<=12）与手动验证（<=10）
### 验收点
1. 新页面全部统一 PageHeader + Card 风格，且与现有 Logs/Usage 不割裂。
2. `/login` 能明确提示 env 缺失/连接失败原因，并提供重试与诊断复制。
3. Settings/Providers/Auth Files/Config/System 的主流程可完成且交互反馈一致。
4. 所有不可逆操作有二次确认 + “不可逆”文案。
5. 空态有引导按钮；错误态可复制 + 重试。
6. dirty 状态下离开 Config 页面会被拦截。
7. 中英切换覆盖新页面（无硬编码）；day/night 两主题均可读。
8. 页面文件行数控制：>600 必拆；可复用组件沉到 `components/`。

### 手动验证步骤（设计验收角度）
1. 逐个点击侧边栏：/ /login /settings /settings/providers /auth-files /config /system
2. 切换主题（day/night）检查表单与卡片对比度
3. 切换语言（en/zh）检查标题/按钮/提示是否覆盖
4. 检查危险按钮：是否都有 confirm 且文案含“不可逆”
5. 检查空态/错误态是否有 CTA 与 Retry
