# 公网登录页与会话鉴权 - 需求分析（生成时间：2025-12-30 12:14）

## 背景与现状
- 背景：CLIProxy Management Center 需要在公网可访问条件下提供安全的管理后台入口。
- 现状/痛点：
  - 目前 management API 依赖服务端 env 固定配置，不支持用户在 UI 上输入连接信息。
  - `/login` 现为健康检查页，不具备真正登录/鉴权与全站拦截能力。
  - 公网暴露下存在 SSRF、密钥泄露、CSRF、开放重定向、暴力探测等风险面。

## 用户/角色
- 管理员（主要）：首次访问后台，输入管理端口与管理员密钥，登录后进行配置/查看。
- 运维/排障人员（次要）：需要查看连接状态、版本信息、日志等（同样需登录）。

## 目标与范围
- 目标（可验证）：
  1) 未登录禁止访问任何管理页面与任何 `/api/*`（除 `/api/auth/*`）。
  2) 登录页仅允许 `https://`，hostname 固定为本站点 hostname，用户只输入 port。
  3) 会话默认记住 30 天固定到期，密钥不出现在前端可读存储（localStorage/JS）。
  4) 登录页具备测试连接、错误分级提示、语言切换与移动端适配。
- 范围（做）：
  - DB 会话存储 + AES-GCM 加密密钥
  - Auth API（probe/login/logout/session）
  - middleware + layout 拆分
  - 改造现有 API 统一 requireSession
  - 修复 Pricing 模型列表加载（改为 server 代理）
- 非范围（不做）：
  - 多用户/RBAC/SSO
  - 多 profile 连接管理
  - 滑动续期
  - 允许任意 hostname 或 http

## 核心场景（5 条）
1) 首次访问任意页面 → 自动跳转登录页。
2) 输入端口 + 密钥 → 点击“测试连接” → 成功显示版本信息。
3) 点击“登录（记住 30 天）” → 跳转到 next 或 dashboard。
4) 登录后调用任意 API 正常；登出后立即失效。
5) 30 天到期后：访问页面/API 重新要求登录。

## 数据对象与字段（关键即可）
- `ManagementSession`
  - `tokenHash`：cookie token 的 hash（DB 不存明文 token）
  - `serverBase`：`https://<hostname>:<port>`
  - `keyCiphertext/iv/tag`：管理员密钥 AES-GCM 加密存储
  - `expiresAt`：固定到期
  - `revokedAt`：登出/吊销
  - `lastUsedAt`：可选，用于排障与运营（不含敏感信息）

## 接口/数据来源
- Cliproxy management API（服务端代理请求）
  - Probe：`GET https://<host>:<port>/v0/management/debug`
- 本项目 API
  - `/api/auth/probe`、`/api/auth/login`、`/api/auth/logout`、`/api/auth/session`
  - 其余 `/api/*` 全部 requireSession

## 约束与假设
- 公网访问：必须考虑 SSRF、CSRF、密钥泄露与暴力探测。
- 仅允许 `https://`。
- hostname 固定为本站点 hostname（`NEXT_PUBLIC_SITE_URL`），端口可变。
- 固定 30 天到期。
- DB 可用（Prisma + Postgres）。

## 边界条件
- 端口非法（空/非数字/超范围）
- 连接失败（超时/DNS/证书）
- 密钥错误（401/403）
- 目标不是 cliproxy 管理服务（无特征头）
- `AUTH_ENCRYPTION_KEY` 缺失或 DB 不可用
- `next` 参数不合法（开放重定向防护）

## 验收标准（可验证）
- 视觉/交互：登录页为全屏居中玻璃拟态，加载/错误/成功态清晰，中英切换可用，移动端可用。
- 功能：全站拦截生效；probe/login/logout/session 正常；到期后强制重新登录。
- 安全：
  - 密钥不落 localStorage；cookie 为 httpOnly+Secure+SameSite=Strict。
  - 非 GET 写接口校验 Origin。
  - 日志不出现密钥。
- 可维护性：新增 auth 逻辑集中在 `lib/auth/*`（或同等集中模块），避免散落。

## 风险与回滚
- 风险：
  - middleware matcher 误拦导致静态资源/登录页不可用
  - canonical hostname 配错导致无法登录
  - 漏掉某些 `/api/*` 未加 requireSession
- 回滚：
  - 优先 `git revert`
  - 紧急降级：临时移除 middleware + requireSession（恢复 env 模式）
