## 【背景与现状】
- 现状：
  - 当前 `app/login/page.tsx` 是“Connect & Health”性质页面（探测 `/api/system/health`），并非真正的“登录/鉴权”。
  - Management API 调用由服务端环境变量驱动：`CLIPROXY_MANAGEMENT_BASE` + `CLIPROXY_MANAGEMENT_KEY`（`lib/management/client.ts` / `lib/management/env.ts`）。
  - 根布局 `app/layout.tsx` 默认渲染 Sidebar，未登录也能进入所有页面。
  - Pricing 页面存在浏览器直连模型列表 endpoint 的实现（`app/pricing/pricing-client.tsx`），不适配“按会话动态端口连接”。
- 新需求（已确认）：
  - 公网可访问。
  - 仅允许 `https://`。
  - hostname 固定为 UI 的 hostname（端口可变），用户只输入端口。
  - 默认记住 30 天，固定到期（不滑动续期）。
  - 未登录禁止访问所有页面与所有 `/api/*`（除 `/api/auth/*`）。

## 【目标】
- 新增“高端登录页”并成为默认入口：锁定 hostname，仅输入端口 + 管理员密钥；支持测试连接/错误分级提示/语言切换/移动端。
- 会话鉴权：默认记住 30 天（固定到期）；管理员密钥不落前端可读存储；服务端 DB 存会话并加密密钥。
- 全站拦截：未登录访问页面重定向到 `/login`；未登录访问 `/api/*` 返回 401 JSON。
- 兼容：现有离线脚本（usage ingest/aggregate 等）仍可继续使用 env 方式（不依赖会话）。
- 修复适配：Pricing 模型列表不再浏览器直连外部 endpoint，统一走 `/api/models`（服务端按 session base 代理）。

## 【非目标】
- 多用户/RBAC/SSO（OIDC/LDAP）不做。
- 多连接 profile 管理（保存多端口/多密钥并切换）不做。
- 允许任意 hostname 连接不做（仅同 hostname）。
- 允许 `http://` 不做。
- 会话滑动续期不做（固定 30 天到期）。

## 【需求拆解】
- Auth & Security
  - httpOnly cookie + DB 会话（token 只存 hash），AES-GCM 加密 admin key
  - 强制 `https://` + 固定 hostname（从 `NEXT_PUBLIC_SITE_URL` 解析）+ 端口校验
  - CSRF 基线：非 GET 校验 `Origin`（配合 SameSite=Strict）
  - open redirect 防护：`next` 参数仅允许站内相对路径
  - 日志脱敏：任何日志/错误不得输出 admin key
- API
  - `/api/auth/probe`（测试连接与特征校验）
  - `/api/auth/login`（创建会话 + 下发 cookie）
  - `/api/auth/logout`（吊销会话 + 清 cookie）
  - `/api/auth/session`（登录态查询，不返回 key）
  - 其余所有 `app/api/**/route.ts` 均 requireSession（兜底，避免漏网）
- UI
  - 登录页：玻璃拟态/渐变背景/加载与错误态清晰/可访问性/语言切换
  - 登录页不显示 Sidebar；应用页正常显示 Sidebar
- 受影响点
  - `app/pricing/pricing-client.tsx` 模型列表改走 `/api/models`

## 【现状证据与定位记录】
- “登录页”现状：
  - `app/login/page.tsx`：当前是健康检查页（`fetch('/api/system/health')`）
  - `app/system/page.tsx`：也有类似的 health 展示
- Management 调用链：
  - `app/api/system/health/route.ts` → `lib/management/client.ts`（`fetchManagementRaw('/debug')`）
  - `lib/management/client.ts`：从 `readManagementEnv()` 读取 env 并设置 `Authorization: Bearer <key>`
  - `lib/env.ts`：当前强制 `CLIPROXY_MANAGEMENT_KEY` 必填（会阻塞“输入 key 登录”的启动方式）
- 直连风险点：
  - `app/pricing/pricing-client.tsx`：浏览器 fetch `NEXT_PUBLIC_MODELS_ENDPOINT || http://localhost:3818/v1/models`（需要改为服务端代理）

## 【实现策略】
- 大方向：
  1) 先落地会话模型 + auth API（probe/login/logout/session）与安全校验（https/host/origin/next）
  2) 再加 `middleware.ts` 与 layout 拆分，实现全站拦截
  3) 最后统一管理端调用：从 session 注入 base/key，并修正 Pricing 直连等受影响点
- 关键约束：
  - 公网仅 https
  - hostname 固定为 UI hostname（端口可变）
  - 固定 30 天到期
  - 不引入重型 auth 框架（保持最小依赖）
