实现方案（公网登录页与会话鉴权）

## 0) 共识结论（已确认）
- 场景：公网访问。
- 安全约束：仅允许 `https://`。
- 地址约束：hostname 固定为 UI hostname（端口可变），用户只输入端口。
- 会话：默认记住 30 天，固定到期（不滑动续期）。
- 拦截范围：所有页面 + 所有 `/api/*`（除 `/api/auth/*`）。

## 1) 威胁模型与安全策略
### 1.1 主要风险
- SSRF：若允许用户输入任意 URL，服务端会代为访问任意地址。
- 密钥外泄：服务端请求 management API 需带 `Authorization: Bearer <key>`，若目标不是 cliproxy，会把 key 发给错误服务。
- CSRF：公网下 cookie 会话的写接口需要防跨站请求。
- Open Redirect：`/login?next=` 若不限制可能被利用。
- 暴力探测：公网登录口会被持续撞库（后续可做限流）。

### 1.2 本任务采用的策略
- 强制 `https://`。
- hostname 固定为 canonical hostname（生产环境用 `NEXT_PUBLIC_SITE_URL` 解析，避免 Host Header 注入）。
- Probe 时校验响应特征头（例如 `X-CPA-VERSION` / `X-CPA-BUILD-DATE`），不符合则视为“非管理服务”。
- cookie：`httpOnly + Secure + SameSite=Strict`，并且固定 30 天到期。
- 非 GET（含 login/logout）校验 `Origin`（可选再校验 Referer 作为补充）。
- `next` 参数仅允许站内相对路径（`/xxx`），禁止 `//`、`http(s)://` 等。

## 2) 最终架构
### 2.1 认证形态
- 浏览器：只保存 `session_token`（httpOnly cookie）。
- 服务端：DB（Prisma/Postgres）保存 session（token hash + serverBase + 加密后的 adminKey + expiresAt）。
- 不使用 localStorage 存密钥。

### 2.2 Canonical Host 与 serverBase
- canonical hostname：`new URL(NEXT_PUBLIC_SITE_URL).hostname`
- serverBase：`https://<canonicalHost>:<port>`
- managementUrl：`${serverBase}/v0/management`

## 3) 数据模型（Prisma）
建议新增：`ManagementSession`
- `id String @id @default(cuid())`
- `createdAt DateTime @default(now())`
- `updatedAt DateTime @updatedAt`
- `lastUsedAt DateTime?`
- `expiresAt DateTime`
- `revokedAt DateTime?`
- `tokenHash String @unique`（sha256 hex/base64）
- `serverBase String`
- `keyCiphertext Bytes`
- `keyIv Bytes`
- `keyTag Bytes`

说明：DB 不存明文 token；cookie 里存明文 token，查询时先 hash 再查 DB。

## 4) 加密设计（AES-256-GCM）
- env：`AUTH_ENCRYPTION_KEY`（32 bytes base64）
- iv：12 bytes random
- aad：建议使用 `serverBase`（绑定上下文）
- 输出：ciphertext + tag（分别持久化）

## 5) Auth API 设计
### 5.1 `POST /api/auth/probe`
- 入参：`{ port: number, adminKey: string }`
- 行为：
  1) 校验 port 范围（1..65535）
  2) 组装 serverBase/managementUrl
  3) 请求 `GET {managementUrl}/debug`（带 Authorization）
  4) 校验特征头；成功返回 `{ connected: true, serverBase, serverVersion, serverBuildDate }`

### 5.2 `POST /api/auth/login`
- 入参：`{ port: number, adminKey: string, rememberDays?: 30 }`
- 行为：
  1) 内部复用 probe 逻辑（或先 probe）
  2) 创建随机 token，写入 DB（tokenHash + 加密密钥 + expiresAt）
  3) set-cookie：`session_token`（httpOnly + Secure + SameSite=Strict + Max-Age=30d）
  4) 返回 `{ ok: true, expiresAt, serverBase }`

### 5.3 `POST /api/auth/logout`
- 行为：
  - 根据当前 cookie 查 session，写 `revokedAt=now()`
  - 清 cookie

### 5.4 `GET /api/auth/session`
- 返回：`{ authenticated: boolean, expiresAt?: string, serverBase?: string }`

## 6) 全站拦截
### 6.1 middleware
- 页面：无 cookie → redirect `/login?next=<path>`
- API：无 cookie → 401 JSON（排除 `/api/auth/*`）
- matcher：必须排除 `/_next/*`、静态资源、favicon 等，避免误拦。

### 6.2 API 兜底
- 所有 `app/api/**/route.ts` 在入口调用 `requireSession()`
- 未通过：统一返回 401（JSON）

## 7) management client 改造

- 新增 `fetchManagementRawWithConfig({ serverBase, key }, path, init)`
