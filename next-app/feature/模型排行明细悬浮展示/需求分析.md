时间戳：2025-12-22 09:42

背景/现状
- 使用概览的“模型排行”仅展示总 Token、缓存命中率与成本总额，无法直观看到输入/输出/思考 Token 的构成，以及输入/输出金额拆分。
- 后端当前 `UsageEvent/UsageDaily` 已记录输入/输出/思考 Token，但 `/api/usage/by-model` 未返回明细字段与价格拆分金额。

用户故事
- 作为运营/管理员，我希望在模型排行中快速查看某个模型的输入/输出/思考 Token 与对应金额，便于理解成本构成与定位异常。

范围/非范围
- 范围内：模型排行行内明细展示（hover + 点击）、后端接口返回明细字段、前端展示与交互、i18n 文案补充。
- 非范围：历史价格回溯、改动计费规则、扩展其它页面/维度展示、重算历史数据。

关键流程（文字）
1. 用户进入“使用概览”页面并看到“模型排行”表格。
2. 在某个模型行触发明细（hover 或点击信息按钮）。
3. 前端展示该模型在当前筛选/时间范围内的输入/输出/思考 Token 与输入/输出金额；若价格未配置则显示“未配置”。

数据/接口假设
- 数据来自 `/api/usage/by-model`（按当前筛选条件）。
- 价格来自 `ModelPricing` 的当前配置。
- 金额按现有规则拆分：
  - Codex：输入金额按 `inputTokens - cachedTokens`，输出金额按 `outputTokens`，思考 Token 计入输出金额。
  - Gateway：输入金额按 `inputTokens`，输出金额按 `outputTokens + reasoningTokens`。

边界条件
- 模型未配置价格：明细中金额显示“未配置”。
- Token 为 0：金额显示为 $0.000（或按现有格式）。
- 触控设备无 hover：需提供点击触发方式。

验收标准
- 模型行支持 hover 与点击方式查看明细（不影响行选择/展开）。
- 明细字段齐全且与当前筛选/时间范围一致。
- 未配置价格时明确显示“未配置”。

风险与降级策略
- 风险：接口扩展影响前端解析；明细展示与行点击冲突；计价规则理解偏差。
- 降级：若接口无法提供明细，前端只展示 Token 明细并隐藏金额项；或暂时仅保留原表格展示。

未解决问题
- 明细展示 UI 样式与交互层级需在 UI 设计阶段确认。
