# 任务计划（Lite）— 用量统计：增加渠道 opencode

## 1. 背景 / 问题
- 需求：在“用量统计/看板”里新增渠道 `opencode`，并能像 `codex` 一样采集并统计它的用量。
- 影响范围：Usage 页面、Dashboard 概览页、聚合作业（Aggregation Pipeline）以及采集脚本（ingest scripts）。
- 期望结果：
  - UI 可筛选 `opencode`，并能看到对应的 tokens / cost / requests。
  - 提供 `scripts/opencode-ingest.ts`（one-shot）与 `scripts/opencode-ingest-loop.ts`（默认 5 分钟一次）。

## 2. 目标与范围
- 目标（3条以内）：
  1) 新增渠道：`opencode`
  2) 增加 opencode 的 ingest 与 5 分钟 loop 脚本
  3) 用量统计（后端查询 + 前端筛选 + 文案）支持 opencode
- In scope：
  - 新增 `lib/opencode-ingest.ts` + `scripts/opencode-ingest*.ts`
  - 后端 API（Usage + Sessions + Aggregation）支持 `opencode`
  - Dashboard/Usage UI 支持 `opencode`
- Out of scope（明确不做）：
  - 不新增 DB schema/migration（沿用 `UsageEvent.sourceType`）
  - 不做 opencode 日志格式的深度兼容（仅对齐当前 Codex rollout jsonl 的解析规则；若 opencode 格式不同需补样例再适配）

## 3. 验收标准（可验证）
- [ ] AC1：`npm run opencode:ingest` 可执行（需要配置环境变量 + DB 可用），且写入 `UsageEvent.sourceType=opencode` 的事件。
- [ ] AC2：`npm run opencode:ingest:loop` 默认每 5 分钟采集一次（可用 env 覆盖间隔），且不会并发重入。
- [ ] AC3：Usage 页面渠道筛选可选 `opencode`，并在选择后查询口径正确（包含历史 day 粒度与当日 events 粒度）。
- [ ] AC4：Dashboard 概览页渠道筛选可选 `opencode`，趋势/Top Models/定价覆盖统计能正确过滤到 opencode。
- [ ] AC5：Sessions 页在选择 `opencode` 时可查看会话列表与事件明细（与 codex 同口径）。

## 4. 证据与定位（必须：路径 + 符号）
- 定位锚点：
  - `scripts/codex-ingest.ts` / `scripts/codex-ingest-loop.ts`：CLI 用量采集脚本范式
  - `lib/codex-ingest.ts`：Codex rollout jsonl → `UsageEvent` 写入逻辑
  - `lib/usage/aggregation-constants.ts` / `lib/api/schemas.ts`：渠道枚举与后端 query schema
  - `app/api/usage/route.ts`：Usage 主查询（UsageDaily + UsageEvent 混合）
  - `app/api/usage/sessions/**`：Sessions 查询（codex + opencode）
  - `components/usage/channel-filter.tsx` / `lib/channel-utils.ts`：前端渠道筛选与展示
  - `lib/dashboard/overview/*`：Dashboard 概览查询（含渠道过滤）
