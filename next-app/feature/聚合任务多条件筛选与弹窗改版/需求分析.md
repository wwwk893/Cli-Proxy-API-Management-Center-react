# 需求分析

- 时间戳：2025-12-19 12:29

## 背景/现状
新建聚合任务目前仅按日期创建，缺少“模型型号/渠道”的组合筛选入口，也没有在创建时提示筛选条件下的数据最早时间点，导致用户容易选错范围或需要多次试错。

## 用户故事
- 作为运营/管理员，我希望按模型与渠道组合筛选并创建聚合任务，以便只重算我关心的子集数据。
- 作为使用者，我希望看到当前筛选条件下“最早有数据时间点”，避免选择无数据日期。

## 范围
- 新建聚合任务弹窗整体 UI 设计与交互升级。
- 模型/渠道多选筛选（含全选/清空）。
- 展示基于原始 usage 事件、本地时区的最早数据时间点。
- 创建任务请求携带筛选条件并由后端处理。

## 非范围
- 历史任务展示/统计卡片不改造。
- 成本回填逻辑不变。
- 不调整现有 ingestion/事件存储策略。

## 关键流程（文字）
1) 用户打开“新建聚合任务”弹窗。
2) 在模型/渠道筛选区进行多选或全选。
3) 系统根据筛选条件查询并展示“最早有数据时间点”。
4) 默认开始日期=最早数据点（若有），结束日期=昨天；用户可调整但仅限过去日期。
5) 提交创建，任务携带筛选条件入库并进入聚合队列。

## 数据/接口假设
- 渠道列表来自 `lib/api/schemas.ts` 中的 `channels` 定义（与现有 usage API 一致）。
- 模型候选来自 usage 事件中出现的模型集合（需要后端提供可用模型列表）。
- 需要新增或扩展接口以支持“按条件查询最早数据时间点”。

## 边界条件
- 日期只能选择过去日期（不能包含今天及未来）。
- 当筛选条件无数据时，提示“无可用数据时间点”，并阻止创建或提示用户调整筛选。
- 时间展示使用本地时区。

## 验收标准
- 模型与渠道支持多选/全选/清空，且组合筛选可用。
- 最早数据时间点展示准确且随筛选实时更新。
- 默认日期符合“最早数据点/昨天”规则，且仅允许过去日期。
- 弹窗视觉与交互明显提升，信息层级清晰。

## 风险与降级策略
- 风险：新增筛选条件后任务唯一性与重复调度处理复杂度上升。
  - 降级：若条件字段导致冲突，可暂时只使用日期唯一性并允许重复创建。
- 风险：最早时间点查询性能或不可用。
  - 降级：查询失败时提示“无法获取最早时间点”，允许用户手动选择过去日期。

## 未解决问题
- 最早数据时间点查询接口的具体实现与表结构（需评估是否在现有 usage 事件表中统计）。
- 模型列表接口是否复用已有 usage 元数据聚合，或新增轻量端点。
