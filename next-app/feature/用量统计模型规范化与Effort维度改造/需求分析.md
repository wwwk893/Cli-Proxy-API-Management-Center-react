时间戳：2026-01-05

背景/现状
- 当前用量统计按模型字符串直接分组；随着“推理强度/档位（reasoning effort）”引入，出现 `-high/-xhigh/-medium/-low` 与 `(high)` 等写法，导致同一基础模型被拆成多行（统计不可读、趋势对比困难）。
- 同时存在 `gpt-5.2-codex / gpt-5.1-codex / gpt-5.1-codex-max` 等独立基础模型：它们不应与 `gpt-5.2 / gpt-5.1` 合并，但也需要按 effort 维度进一步拆分与汇总。
- 数据源约束：
  - cliproxy：只能拿到 DB 内事件/聚合后的数据（原始 API 明细不在硬盘上，无法离线重算）。
  - codex/opencode：硬盘上有本地数据，理论上可重入库补历史，但本任务主要解决“统计口径/展示”而非补数。

用户故事
- 作为管理员/运营，我希望在“模型排行/用量统计”中默认按基础模型汇总，看清总量与成本。
- 同时我希望能按推理强度（effort）查看分布与筛选（例如只看 xhigh），用于成本与性能分析。
- 当出现异常时，我需要能回溯到原始模型串（modelRaw）与来源渠道定位问题。

范围/非范围
- 范围内：
  - 数据层新增 `modelRaw/modelCanonical/effort` 维度（双字段追溯）。
  - ingestion 与 DB backfill 回填，保证历史与新增数据统一。
  - 统计 API 与 UI 支持“基础模型聚合 + effort 分布/筛选 + 维度切换”。
- 非范围：
  - 改变计费规则/价格口径；历史价格回溯与重算。
  - 新增告警、监控或自动化报表。

关键流程（文字）
1) 用户进入 `/usage` 用量统计页面。
2) 通过过滤条选择时间范围、渠道、来源等；默认维度为“基础模型（modelCanonical）”。
3) 在模型排行中查看每个基础模型的总请求/总 Token/缓存命中/成本；并可通过“effort 分布”理解各档位占比。
4) 用户可选择：
   - 维度切换：基础模型 / 基础模型+effort / 原始模型（排错用）
   - effort 筛选：low/medium/high/xhigh 多选
5) Dashboard Top Models 与 /usage 展示口径保持一致（避免同口径下展示不一致）。

数据/接口假设
- 统计数据源：`UsageEvent`（明细）+ `UsageDaily`（历史聚合）。
- 新增字段（B-完整）：
  - `UsageEvent.modelRaw`：原始模型串（保留追溯）。
  - `UsageEvent.modelCanonical`：仅剥离末尾 effort 后的基础模型。
  - `UsageEvent.effort`：显式字段优先，否则从 `modelRaw` 末尾解析；值域为 `low|medium|high|xhigh`（统一小写）。
  - `UsageDaily.modelCanonical/effort`：用于历史区间的快速统计与过滤。
- API 方向：
  - `/api/usage/by-model` 支持按 `modelCanonical/effort/modelRaw` 维度聚合（具体参数命名由实现方案定稿）。

边界条件
- effort 缺失：`effort = null`，在 UI 中归到“未标注/unknown”分组（可折叠/可筛选）。
- 误判风险（已接受）：由于主人选择“对所有模型统一解析”，若存在某些真实模型名以 `-high` 结尾但并非 effort，将被拆分；需要在实现方案中提供“回退/例外表”能力（例如通过配置表禁用某些 modelRaw 的解析）。
- `gpt-5.1-codex-max`：末尾 `-max` 不是 effort，必须保留为基础模型的一部分。
- 同一 canonical 下价格配置不一致：UI 需提示“定价冲突/未配置”，避免拆分成本显示误导。

验收标准
- 默认榜单按 `modelCanonical` 汇总：`gpt-5.2-high/xhigh/(high)` 合并为 `gpt-5.2` 一行；`gpt-5.2-codex*` 独立展示。
- effort 可筛选/可展开：同一基础模型可按 low/medium/high/xhigh 展示占比与明细。
- 同时间窗同筛选条件下，迁移前后总请求/总 Token/总成本一致（仅分组维度变化）。
- modelRaw 可追溯：排错时能定位具体原始模型串与来源。

风险与降级策略
- 风险：解析规则误判导致少量模型被错误归并/拆分。
  - 降级：提供“维度切换=原始模型”与“禁用解析/例外表”能力，必要时临时回退到 raw 分组。
- 风险：按 canonical 输出后，`ModelPricing` 仍按 raw 配置导致“拆分金额未配置”提示增多。
  - 降级：价格查询 fallback（canonical→raw）；UI 对冲突/缺失显式提示。

未解决问题（后续在 UI/实现方案阶段确认）
- `/usage` 页过滤器：effort 筛选与维度切换的放置位置、默认状态与交互节奏。
- 模型筛选（FilterPopover）是否按 canonical 展示、是否需要“显示 raw 变体”的高级开关。
- Dashboard Top Models 是否同步显示 effort 分布，或只保持 canonical 聚合。
