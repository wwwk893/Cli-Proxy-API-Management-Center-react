## 【背景与现状】
- 现状：同一“基础模型”因为渠道/推理强度（reasoning effort）等差异，出现 `-high/-xhigh/-medium/-low` 或 `(high)` 这样的后缀，导致“模型排行/统计”被拆成多行，难以看总量。
- 现状：存在 `gpt-5.2-codex / gpt-5.1-codex / gpt-5.1-codex-max` 等“独立基础模型”，它们与 `gpt-5.2 / gpt-5.1` 不同，但同样也会出现 effort 维度（如 `gpt-5.1-codex-max-xhigh`）。
- 现状：数据来源包含 cliproxy（管理 API，仅 DB 可用）、codex/opencode（本地可重入库，但本任务以 DB 内 backfill 为主）。

## 【目标】
- 数据口径：新增 `modelRaw/modelCanonical/effort` 维度（双字段追溯），默认按 `modelCanonical` 汇总；需要时可按 `effort` 细分。
- effort 解析策略：对所有模型统一解析（仅剥离末尾 `-(low|medium|high|xhigh)` 或 `(low|medium|high|xhigh)`；`gpt-5.1-codex-max` 的 `-max` 不视为 effort）。
- 展示目标：用量统计界面支持“基础模型聚合 + effort 分布/筛选”，并保留“原始模型串（modelRaw）”用于排错与追溯。
- 一致性：迁移前后同时间窗/同筛选条件下，总请求数/总 Token/总成本不变（仅分组维度变化）。

## 【验收标准】
- [ ] AC1：默认按 `modelCanonical` 汇总；`gpt-5.2-codex*` 与 `gpt-5.2` 不合并；`gpt-5.2-max` 的 canonical 为 `gpt-5.2-max` 且 effort=null
- [ ] AC2：支持 3 种 View Mode（基础模型 / 基础模型+Effort / 原始模型排错）+ Effort 多选筛选（含“未标注/unknown”）
- [ ] AC3：迁移前后同时间窗同筛选条件下，`SUM(requestCount/totalTokens/costUsd)` 一致（仅分组维度变化）

## 【非目标】
- 不改变计费规则（Gateway/Codex 的计费口径保持现状）。
- 不引入新的数据源（本任务仅规范化现有用量数据与统计口径）。
- 不做“历史价格回溯/按时间点价格重算”（仍以当前 `ModelPricing` 为准）。

## 【需求拆解】
- 数据层（B-完整）：
  - `UsageEvent`：新增 `modelRaw`、`modelCanonical`；`effort` 继续保留并统一写入（显式字段优先，否则从 `modelRaw` 末尾解析）。
  - `UsageDaily`：新增 `modelCanonical`、`effort`（用于历史区间的高效聚合与筛选）。
- 入库层：
  - cliproxy/codex/opencode 统一走 `normalizeModel()`，确保 `modelRaw/modelCanonical/effort` 一致。
- 迁移与回填：
  - Prisma migration 新增列（仅新增，避免不可逆覆盖）。
  - DB 内 backfill：为历史数据填充 `modelRaw/modelCanonical/effort`；并补齐 `UsageDaily` 新列。
- API：
  - `/api/usage/by-model` 增加分组维度支持（默认 modelCanonical；可切换到 raw / canonical+effort）。
  - `/api/models`（模型列表）需考虑“展示名/筛选项”是否按 canonical 归并（由 UI 设计稿决定）。
- UI：
  - 使用概览页：模型排行默认按基础模型聚合；新增 effort 分布展示与过滤；提供“维度切换（基础模型 / 基础模型+effort / 原始模型）”。
  - Dashboard Top Models：展示口径与 /usage 一致（避免同一时间窗两个页面口径不一致）。
